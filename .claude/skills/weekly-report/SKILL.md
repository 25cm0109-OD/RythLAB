# 週報の記録

ユーザーが言った内容を、週報ファイルに書き写し、GitHubにpushし、そのあと提出サイト（Prairie）にも同期する。

## 管理方針
- **GitHub（`docs/weekly-reports/`）が正本。** 見やすいのでGitHubで管理し、Prairieは提出用に同期するだけ。
- 流れ: ローカルのmdを更新 → commit & push → Prairieに反映。
- リポジトリ: `25cm0109-OD/RythLAB`（private）。ghは `25cm0109-OD` でログイン済み。

## 絶対ルール
- **ユーザーが言った内容だけを書く。** 文章を膨らませない、言い換えで長くしない、補足や推測を足さない。ユーザーの言葉をほぼそのまま使う。
- 言われていない項目は触らない。空欄の項目はそのまま残す。
- ローカルに書いたあと、必ず「GitHubへのpush」と「Prairieへの同期」まで行う（ユーザーから確認なしで提出してよいと言われている）。

## ファイル
- `docs/weekly-reports/<週の月曜>_<週の日曜>.md`（例: `2026-11-09_2026-11-15.md`）
- 該当週のファイルが無ければ、下の形式で新規作成する。ある場合は既存の内容を残して更新する。

## 形式
```
# 週報 <開始日> ～ <終了日>

GR6 【iOS/Android】RythLAB

## ① 進捗状況
M/D(曜)の予定
・やること
M/D(曜)の実績
・やったこと

M/D(曜)の予定
...

## ② 問題点

## ③ 次週の予定

## 教員コメント
```

## 更新のしかた
- 予定を言われたら、その日の「予定」に書く（実績の見出しも一緒に作り、中身は空にしておく）。
- やったことを言われたら、その日の「実績」に書く。
- 日ごとのブロックは空行で区切り、日付順に並べる。
- 問題点・次週の予定・教員コメントは、言われたときだけ書く。

## GitHubへのpush
- 週報を更新したら、`docs/weekly-reports/` の変更だけをcommitしてpushする（例: `週報 11/16～11/22 更新`）。
- 他の作業中の変更はこのcommitに混ぜない。

## Prairieへの同期
GitHubにpushしたら、組み込みブラウザ（`mcp__Claude_Browser__*`）で提出サイトにも反映する。確認なしで保存してよい。
- 週報一覧: `https://prairie.cmserver.jp/report`（ここから該当週を選ぶ）
- ログイン済みのことが多い。ログイン画面なら、ユーザーにブラウザ上でログインしてもらう（パスワードは入力しない）。
- 手順
  1. 週報一覧で該当週（ファイル名の週）を選んで開く。「提出済」に行があれば「詳細」→「週報編集」（`/report/edit/<id>`）。「未提出」にあるなら新規提出（サイトの「週報の提出」`/report/input`）。
  2. フォームは「進捗状況」「問題点」「次週の予定」の3つのテキスト欄。**まずWeb側の現在の値を読む**（ユーザーがWebで直接直した内容が残っていることがある）。
  3. ユーザーが言った変更だけをWeb側の値に反映して「保存」を押す。言われていない部分は触らない。
  4. 保存後に詳細画面を読み直し、反映されたか確認する。
- Webの内容がローカル（GitHub）と食い違っていたら（Webで直接直されている等）、ユーザーが言った変更以外は触らず、食い違いがあったことを一言伝える。GitHubが正本なので、Web側にだけある変更はユーザーに確認してからmdへ取り込む。
- 「教員コメント」は教員が書く欄なので、Webには書かない。
